# RAPID-MIND visual contract

Source: owner UI refinement brief, AGENTS.md, and docs/RAPID_MIND_VISUAL_FOUNDATION.md.

Mode: Operate. Preserve the established Operational Humanitarian UI, logo, Inter font stack, light appearance and existing language controls. This is refinement, not a new visual identity.

ENERGY 1 / RHYTHM 2 / MOTION 1. Calm surfaces; grouping changes with the task; movement only for navigation feedback. Honor reduced motion.

- Keep Ink #0F172A, Teal #0F766E, Slate #64748B, Soft Gray #F1F5F9, White #FFFFFF and all existing semantic color tokens. Teal identifies ordinary actions; red remains exceptional for T0/high severity.
- Reuse darker shades already present in the application for readable text. Do not alter the brand token values to repair contrast. Report any remaining conflict.
- Field forms use a bounded reading width. Desktop clinical and operational workspaces use the available width for queues, records and tables.
- Use 4/8/12/16/24/32 px spacing steps, 14–16 px ordinary text, 13 px metadata and 20–24 px page headings. Existing explicit clinical text remains unchanged.
- Controls have at least 44 px touch height. Icon-only controls also have 44 px width. Existing native checkbox/radio labels provide the touch area.
- Borders group records; elevation is reserved for overlays and persistent emergency actions. Avoid nested decorative containers.
- Mobile navigation stays discoverable, supports Escape and returns focus. A desktop sidebar is not an invisible focusable mobile menu.
- Tables keep comparison columns, with contained horizontal scrolling where needed. Forms and action groups wrap at their content limits.
- Keep every clinical decision, status, KPI meaning, API contract, encryption boundary, route and persistence behavior. Visual consistency never authorizes a logic change.

No new fonts, imagery, logos, decorative statistics or theme switch are introduced. Findings and actual visual evidence belong in docs/ui, not inferred from successful compilation.
